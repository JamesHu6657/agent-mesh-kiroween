# Agent Mesh v1 — M3-lite Acceptance Addendum (N18–N27)

Public addendum to [docs/acceptance-checklist.md](acceptance-checklist.md) defining checklist items **N18–N27** for Milestone M3-lite (real adapters with evidence-driven launch). Reconstructed from [docs/m3-gate-report.md](m3-gate-report.md) and `.kiro/specs/m3-*/requirements.md`.

## N (continued). M3-lite real adapter evidence, parsing, and cleanup

| ID | Req | Plan | MS | Check | Expect |
|---|---|---|---|---|---|
| N18 | §6 S | M3-lite | M3 | Adopted run whose wrapper exits while a SIGTERM-ignoring, env-less member of its process group stays alive; also merge test step leftover cleanup (`test_recovery_adopt_seen`, `test_run_release_seen`, `test_runtargets_race`, `test_m3_gatefix`) | Run stays open and lease (`task:<id>` / `merge:<prj>`) stays held through grace; members are recorded in `seen.json`; survivors are terminated (`SIGKILL`) before release, or held fail-closed on unusable/uncertain scans until cleared or `run release --force-seen-unusable`; `doctor --check-invariants` stays clean |
| N19 | §2 S | M3-lite | M3 | Task create/assign/reassign/retry on a vendor agent in strict evidence mode; vendor lead turn in M3-lite (`test_adapter_evidence`, `test_vendor_lead_gate`) | Launch allowed only when the latest successful probe row matches version `V`, the latest committed results file matches `V`, `validate()` is clean, and `S-X-1` and `S-X-6` pass; otherwise rc 13 `ADAPTER_UNSUPPORTED` with `details.milestone:"M3"` and `details.reason` in `{no_probe_version, no_smoke_evidence, evidence_stale, evidence_invalid, launch_cases_failed}` without spawning any subprocess; testing results-dir override ignored outside testing mode; vendor lead turns refused by default in M3-lite |
| N20 | §2 S | M3-lite | M3 | `mesh adapter show <id>` and `mesh adapter list` against committed probe and smoke results (`test_adapter_evidence`, `docs/adapters.md`) | Per capability reports `verification`, `verified_at`, `verified_version`, and `results_file` from the latest results file (`stale` on version mismatch); adapter status is `verified` only if every `supported:"yes"` capability has `verification:"smoke"` (otherwise `partially_verified`); prints `launch_enabled`, `launch_milestone`, `launch_reason` |
| N21 | §2 S | M3-lite | M3 | Capture writer and promoter (`tests/tierlib.py`, `test_tierlib`) for `tests/fixtures/real/` and `tests/smoke/results/` | Every captured/promoted fixture and results file carries a `.meta.json` sidecar with `{command, captured_at_utc, sha256}`; overwrites of existing paths and `synthetic_*` names are refused; additions are coordinator-promoted and `test_fixture_hashes` stays passing |
| N22 | §2 S | M3-lite | M3 | Live help probe differs from committed help fixture (`test_helpdiff`, `tests/fixtures/real/{droid/1.6.0,agy/1.5.3,kiro/3.1.0}`) | Captures new version directory with sidecars, reports flag diff against emitted flags in `docs/adapters.md`, and marks mismatched old-version capability rows `stale` |
| N23 | §2 S | M3-lite | M3 | N1 and N4 integration tests after evidence-driven launch lands (`tests/integration/test_adapters.py`, `test_tasks.py`, `test_adapter_evidence.py`) | N1 asserts `launch_enabled == effective_launch(...)` over the daemon's results directory (N1 recorded as superseded by N23); N4 keeps its agy refusal assertions plus `details.reason:"no_smoke_evidence"` |
| N24 | §2 S | M3-lite | M3 | Real output `parse()` across vendor adapters on committed real stream fixtures and synthetic robustness fixtures (`test_adapters_droid_real`, `test_adapters_kiro_real`, `test_adapters_agy_real`, `test_adapters_vibe_real`) | Parses real `final_text`, `session_id`, and `usage` from committed vendor captures without raising on unknown, non-object, malformed, truncated, or undecodable lines; ignores synthetic result shapes for evidence; synthetic robustness fixtures are named `synthetic_*` and never change capability verification |
| N25 | §2 S, §0 S | M3-lite | M3 | Smoke harness gating and safety invariants (`tests/smoke/harness.py`, `test_smoke_harness`, `test_smoke_cases`, `test_smoke_e2e_gate`, `test_smoke_kiro`) | Skips all smoke tests and spawns no vendor process unless `MESH_SMOKE=1` and the adapter is listed in both `MESH_SMOKE_ADAPTERS` and `MESH_SMOKE_CONSENT`; requires `MESH_SMOKE_MAX_RUNS`, refuses model `auto` and non-absolute binaries, writes only under `MESH_SMOKE_OUT` (`/tmp/mh-*`), never uses repo cwd, redacts secrets, and leaves offline tests free of `MESH_SMOKE*` env vars and tripwire hits |
| N26 | §2 C, §5 C | M3-lite | M3 (consent, stretch) | Optional real code-task e2e demo (`tests/smoke/test_e2e.py`, `e2e-N26-droid-1.6.0-*.json`) | With consent, a `droid` `dev`-profile task commits a file in a no-remote fixture repo, submits with `git.dirty:false`, passes the merge test step, creates a two-parent integration merge commit, and pushes nothing; if skipped, the gate report records "not run" |
| N27 | §2 S | M3-lite | M3 | Evidence-backed adapter docs and gate report (`docs/adapters.md`, `docs/m3-gate-report.md`, `tests/unit/test_docs_m3.py`) | Lists every CLI's status word, `launch_enabled` with reason, results file or "not run", each droid smoke case, the deferred list, the N26 result, and recorded credit spend, matching the committed results files |
